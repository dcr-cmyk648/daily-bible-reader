# Bounded supervisor authoring

Stages C and D implement the October 10 accepted supervisor work order. C permits
one distinct reading per 90-minute wake; D permits at most three, with five minutes
reserved for checkpointing. Daily and review automations remain ACTIVE. D alone
replaces the two legacy Henry author schedules after its acceptance gates pass.
Installation verifies committed closure bytes, offline ChatGPT login/version/tool
isolation, and the exact installed native source/manifest/config/launcher hashes
before replacing the supervisor pointer. It never performs a paid API call or
availability/model probe.

The accepted D outer coordinators use `gpt-6-luna` / low for rote command,
connector and receipt execution. Preserve the existing daily/review schedules,
project and ACTIVE status; the manager applies this model change after genuine C
acceptance. They never author, review prose, invent approval/health or decide a
retry. Uncertainty and denial remain visible. Archive only their own code-verified
healthy completed run. Substantive child models remain unchanged below.

The installed CLI chooses actual earliest-deadline-first forward work from an
authenticated Detroit current-through-T+7 health measurement and original native
job journals. A hash-bound rolling work order names exactly one reading. Daily
research, synthesis, independent review and one permitted Henry editorial repair
use fresh `gpt-6.1-sol` / high / `--ephemeral` executions through the existing local
ChatGPT login. This is the narrow authorized exception to primary-task authorship;
it grants no general delegation, runtime AI, paid API, or alternative model use.
Shell, apps, plugins, MCP and agents are disabled. Only research enables web search.
The original Henry controller uses `gpt-6-luna` / medium and its controller-proven
`gpt-5.6-luna` / low fallback; source, ownership, submission budgets and cooldowns
remain authoritative.

Consultation requires actual successful completed page access. Lossy CLI snippets
are discovery evidence only. In `bounded_https` mode code retrieves a completed
open's exact public HTTPS page anonymously, checks DNS and every redirect, enforces
an absolute deadline and size limit, then matches the selected excerpt against the
returned bytes. Full modern page bodies are transient. Persisted evidence records
actual event/URL/fetch hashes, access limits, paraphrased notes and rights-limited
short quotations. The verified local Henry archive contributes only commentary
atoms. Registry records remain immutable; additions preserve earlier provenance.
Independent works are counted separately from locators and mirrors. Claims still
require substantive source evaluation under the editorial and rights policies.

Every dispatch reserves its durable budget before execution. An uncertain dispatch
is parked without replay. Accepted raw output and admission hashes are checked on
reuse. One malformed output may receive a repair bound to its exact failed bytes;
one substantive daily changes request may receive a revised study and fresh review.
Author kind budgets never reset when an input or wake changes. Each exact native
review basis has two transport attempts; reading-wide capability/uncertainty
blocks persist across bases. Only validated native changes create a new basis. Native
Henry editorial repair also retains its one-packet repair limit. Review thread IDs
must differ from all actual author and repair threads. Machine validation alone
never approves prose.

When a new daily draft lacks a reviewed Henry library entry, C records
`waiting_henry`; it does not invent a fallback. The native read-only exact-reading
selector admits a dependency only from the same canonical journal's current EDF
observation, persisted rolling order, waiting job and accepted synthesis bytes.
The native session repeats that selector after capability preflight. Once the
library is reviewed, the daily job resumes the exact saved research/synthesis,
attaches the newest checksum-bound layer and receives independent full-study
review. Local promotion rechecks the daily approval, native approval, source input,
library and original target hashes before each write.

The B publication protocol remains content-first and pointer-last. A daily
transaction carrying a native Henry approval requires exact remote content and
metadata readback plus authenticated named-reading health before emitting the
native completion receipt. It can therefore complete the new devotional and its
Henry dependency in one publication. A fallback-only transaction never emits that
receipt. Terminal wake metadata survives all status connector handoffs, and
`runComplete` becomes true only after the status transaction completes.

Thin prompts must finish the shell handoff/dispatch cell, then finish the one
authorized native connector cell, then materialize its receipt and resume in a
later cell. Never repeat a dispatched upload/update because receipt/resume was
rejected or interrupted: recover the retained native result and exact operation
receipt through the existing reconciliation protocol. A rejected resume conveys
no new authority and does not erase the durable dispatch.

`compatibility` produces a read-only hash-bound four-lane report. Original native
event heads, sessions, attempts and approved artifacts are preserved. Unsupported
C daily jobs are parked; they, reserved/uncertain children and incomplete publications
block the A rollback command from allowing legacy daily replay. The report does not itself restore automation definitions
or authorize a legacy daily replay. Manager-controlled routing restoration must
use the accepted exact four-lane snapshot and resolve every report gate first.

C fixtures cover orchestration, actual native dependency/repair/finalization,
process cancellation and publication authority. Injected source/validator/model
fixtures are explicitly identified. Real GEN15 Henry repair of its existing
published devotional fallback, a genuinely new GEN16 daily-to-Henry dependency,
installed runtime acceptance and D routing/cooldown/rollback acceptance
remain separate manager gates. Historical review/publication and protocol refresh
retain their existing policies. D calls the native `historical-selection/v1`
read-only selector before protocol backfill, only after forward completeness.
It receives an in-memory authorization from actual authenticated health and the
original manifest-backed selector. The same native module/context passes it to
the author session, which rechecks health and selection after preflight before
mutation. Never serialize or substitute that reference, a health Boolean, owner,
lease, cooldown or budget. Finalized native pins and genuine installed acceptance
remain release gates. Seven consecutive scheduled
publications remain a sustained service gate; a fixture or one manual reading
does not satisfy it. No reader/backend or selected public asset promotion is
included without the installed-iPhone release gate.
