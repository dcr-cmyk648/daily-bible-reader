## Decisions in force

- Hosting remains an Apps Script HTML-service web app executing as the accessing user. Google identity, the exact two-user server allowlist, the reader-code enrollment, and Drive permission must all succeed; failures close access.
- The private GitHub repository `dcr-cmyk648/daily-bible-reader` stores source and code-only CI history. GitHub Pages is disabled and GitHub is not in the runtime data path. Deployment remains an explicit, reversible clasp/Apps Script release after local and CI validation; no Google credential is stored in GitHub.
- Reader codes are tied server-side to `Dustin` or `Shane`. The verified enrollment is remembered in per-user Script Properties, with the raw code retained only as an IndexedDB device fallback.
- Drive is canonical for private plans, commentary, and source metadata. The Google Sheet remains an append-only/revision-aware comment event log with server identity, timestamps, locks, and idempotent request IDs.
- A multi-chapter day is one reading ID, one ordered `passages` array, one Scripture page, and one shared discussion.
- The app opens to a dark full-month calendar. A date click selects it and updates a passage/progress card below; a separate date-specific button opens it. Every date has one blue Dustin dot and one amber Shane dot, filled independently from active comments. The authoritative body-free Sheet activity check runs before offline preparation, whenever the calendar opens, and whenever the installed app resumes; no reading must be opened first. Each reading has orientation, Scripture, and commentary pages; the same comment form appears on all three. **Finished** returns to the calendar. The internal testing override remains schema-tested but has no reader-facing panel.
- ESV is the only displayed translation. Each chapter is fetched server-side as a separate official API request and combined only in the current response. Policy version `esv-api-2026-08-08-v3-network-only` disables all persistent ESV caching, so the seven-day private-content window never creates an ESV-storage issue.
- Private commentary, source metadata, comment drafts/outbox, and completion state may be retained locally for up to seven days. No service worker is registered. ESV requires a connection.
- Runtime AI remains disabled. Research and synthesis are prepublication work performed one reading at a time.
- Advance generation is proposed as a scheduled Codex/ChatGPT prepublication task with a seven-day private draft target, a separately measured reviewed/published buffer, and an Apps Script deterministic health warning. It is documented but not enabled; no OpenAI API or runtime model would be added to the reader.
- The editorial stance treats Scripture as true and divinely inspired, uses a presumptively literal reading where the text is not clearly figurative, and still steel-mans substantial competing interpretations. Scripture's presentation of prophecy, miracle, divine action, and explicit attribution is the working presumption; methodological naturalism is not treated as a neutral baseline. Displacing those claims requires very strong positive textual, manuscript, linguistic, or historical evidence independent of first excluding the supernatural. Secular and historical-critical sources remain useful for context, language, material culture, and serious counterpositions, but broad source coverage does not grant them equal epistemic authority or force them into the short daily article. The two readers are assumed to have doctoral-level scientific training and extensive biblical/theological familiarity. The daily main path is one passage-driven, source-grounded article rather than a fixed number of insight cards. It should be rigorous without sounding academic for its own sake: plain words, natural transitions, one clear movement per paragraph, and a concrete connection to judgment or action. Every displayed unit must stand alone within that day's Scripture. Main claims use claim-adjacent numerical citations tied to one source-note list. The comprehensive Markdown renders as passage-specific, separately collapsed deep-study sections, followed by a separately collapsed source audit below comments and page navigation.
- The complete long-term canon/order, launch start date, future-lock behavior, browsing horizon, and desired recurring commentary length still require confirmation before the new plan is generated.
