# Independent daily preparation runtime

The Cortan daily study service uses its own installed
`scripts/start-cortan-daily-study-workspace.ps1`. The Henry reviewer continues to
use `scripts/start-cortan-daily-workspace.ps1`. Each bootstrap pins an accepted
commit and creates a pristine offline clone with the four verified canonical
private-store junctions. Neither bootstrap generates or publishes content.

Keep these release pins independent. A Henry-only runtime upgrade must not change
the daily bootstrap. A daily test or workflow repair must not change the Henry
bootstrap, installed runtime or saved Henry tasks. For a daily release, validate
the accepted code and real private stores, then align the daily bootstrap, the
current section of the canonical `docs/CORTAN-DAILY-SERVICE.md`, and the existing
daily heartbeat together. Preserve historical release records as history, not
current preflight requirements. Read back the installed script and saved prompt.

The daily preparation contract still owns one earliest-gap work order and one
exact private publication at a time within current-through-T+7. A successful
bootstrap or compatibility check does not prove that a devotional was published
or that the full horizon is ready. The manager must resume the preserved work
order through research, source review, all gates and genuine live readback.

Tests must distinguish historical calibration scenarios from the changing
prepared-prefix fixture. Historical scenarios build an explicit prefix from the
immutable active calendar; current-content tests derive the expected count from
the current validated fixture. Successive prefix-extension regression checks
exercise the real extension and content validators, while drift rejection and the
fixed 39-reading factual Celebration bridge remain enforced.
