# Testing strategy

`npm run check` is the local milestone gate. It uses no network and no real ESV/Google data.

## Automated layers

- Repository safety: candidate/staged path and content scanning, ignored private-directory coverage, secret patterns, ESV payload indicators, and generated bundle inspection.
- Content validation: schemas are syntactically valid; exactly seven active bridge readings; stable IDs/order/source-day mapping; grouped chapter arrays; the separate 92-day factual reference schedule; cited source IDs/statuses; coverage/generation/rights metadata; and no real Scripture payload.
- Ignored private-content validation: exact fourteen-file bridge allowlist, exactly three `commentary/v3` single-synthesis records plus four explicit `commentary/v2` placeholders, content hashes, all included sources represented in the main synthesis, source-set association, single-source disclosure, inaccessible-source integrity, and no stored Scripture or risky HTML.
- Source-registry validation: exact schema, unique works/locators, genuine access evidence for `consulted`/`included`, no snippet/catalog-only consultation, status/readings consistency, rights-aware raw-storage rejection, and no raw-text fields.
- Matthew Henry pipeline tests: OSIS/canonical reference parsing, synthetic SWORD `zCom4` decoding, shared-range preservation, exact commentary atomization/hashes, exclusion of embedded Scripture transcription from worker/runtime data, non-display verse anchors, normalized book/chapter/range units, strict legacy/current output/runtime/portable-store schemas, duplicate/missing/unexpected verses, invalid source-unit/atom citations and parent linkage, direct-voice warnings, source/prompt/schema/model invalidation, resume skipping, compact cited-atom export, Detroit single-reading and inclusive today-plus-two schedule resolution, Spark-only/window/corpus locks, content-addressed no-Scripture manifests/readings, local checksum enforcement, and safe Codex worker flags. Fixtures contain only conspicuously fabricated source and Scripture-like text.
- Schedule unit tests: source days 54–60, Micah multi-chapter grouping, Detroit civil-date arithmetic, both DST transitions, fixed and testing-day starts, six-day bridge lookahead, lock under narrower configuration, past access, test override, exact partial-passage bounds, earlier-reading continuity links, four-stream invariants, and book-introduction/immediate-chapter-1 adjacency.
- Calendar-flow tests: complete Sunday-based month grids of 28–42 cells, Detroit/DST date placement, missed/today/look-ahead/locked states, selection without navigation, date-specific open action, sanitized two-reader roster and completion map, queued offline creates and retractions, maximum-42 body-free activity batches, and plan-versioned completion persistence.
- Provider-policy tests: live network-only persistence refusal plus synthetic-policy coverage of 500 total, half-book bound, eviction-before-write, seven-day expiry, replacement, long chapter, short one-chapter book rejection, required attribution/policy metadata, and no fallback translation.
- Authorization unit tests: Dustin/Shane code-hash binding, swapped/missing code rejection, versioned per-user enrollment, enrollment account/author binding, hash-rotation invalidation, owner/friend, anonymous, third user, active/effective mismatch, manifest permission failure, arbitrary file-ID rejection, and browser identity spoof rejection.
- Comment tests: create/edit/delete materialization, author ownership, stale-revision collision, idempotent retry, two-user collision, reading association, size limits, and HTML/script retained only as inert text.
- Highlight tests: server-derived identity/time, exact passage-bound validation, independent two-reader marks on one verse, owner-only removal, immutable revisions, idempotent retry, safe overlap rendering, optional-client isolation, and no installed-reader IndexedDB migration.
- Frontend tests: private-cache plan/expiry behavior, current-and-next priority selection, exact selected-day verse extraction from ESV-shaped and fabricated partial-chapter responses, two-reading volatile Scripture-window wiring, malformed-draft normalization, paste/input unlock state, persistent-storage refusal, code-first/enrollment-compatible RPCs, explicit forget-access flow, compact full-month selection, two colored completion dots, date-specific action, consecutive commentary readiness and first-gap behavior, session-only startup-field allowlisting, absence of reader-facing development controls, three reading pages, grouped multi-chapter rendering on one Scripture page, a source-grounded article without insight cards, claim-adjacent numerical citations and numbered notes, shared discussion before custom collapsed deep-study sections, Finished return, always-dark styling, restricted version-update URLs, expected state labels, and absence of API keys/real ESV in generated output.
- Content-automation tests: Detroit date/DST selection, consecutive draft/live buffers, earliest-gap priority, approval/hash/manifest failure modes, explicit generation gate, stable one-reading work-order IDs, complete multi-passage plan handoff, schema validation, and a read-only scheduler-to-skill CLI path.
- Editorial tests: every daily introduction, summary paragraph, takeaway, and comprehensive synthesis must stand alone within that day; the durable workflow requires plain, practical prose, treats supernatural biblical claims as the working presumption, keeps naturalistic assumptions from functioning as evidence, records critical-source affiliation and synthesis priority, forbids anonymous meta-rule prose, and permits prior-day continuity only when the current unit still makes sense by itself.
- Apps Script wrapper test: execute `doGet()` against a strict mock of Google's current `HtmlOutput.addMetaTag` allowlist so unsupported tags fail locally instead of breaking the deployed page.
- Pages-PWA tests: exact public-config shape; token memory-only behavior; full-scope requirement; `scripts.run` endpoint/body/auth; RPC allowlist and concurrent-handler isolation; 401 closure; immutable SRI asset confinement; no executable inline script; public-only service-worker URL set; config/API bypass; network-first release lookup; explicit activation; one-release rollback; and isolated publication that never deletes stable releases.
