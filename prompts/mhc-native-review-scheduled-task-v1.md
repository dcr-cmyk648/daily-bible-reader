# Native Henry Terra review/attach lane

After native generation, fetch `origin/main`, create an isolated worktree, and verify/link existing ignored private stores. Use no generation model. First run exactly `npm run mhc:native:review:work-order`; use its one safe JSON work order rather than scanning review-staging directories. `action=none/state=completed` or `no_review_handoffs` is a successful no-op. Any `state=blocked` fails closed: report only its safe state/stage/code and do not inspect private atoms or attempt review.

For `action=review`, use only the selected reading's exact `review-handoff.json` to locate its bound work item; process no second reading. Run `npm run mhc:native:review:prepare -- --work-item <work-item>`, directly compare every condensation with every cited atom in ignored staging, and create a schema-valid approved all-assertions-true schedule review only after that comparison. Create `review-approval.json` under the same staging directory, binding the exact handoff, review-candidate, and approved-review SHA-256 values. Apply only with `npm run mhc:native:review:apply -- --work-item <work-item> --review <approved-staged-review>`.

For `action=resume_apply`, use the selected reading's exact validated approval binding and selected review handoff to locate its bound work item, then rerun only `mhc:native:review:apply`; do not regenerate or conduct a second editorial review. For `action=recover_finalize`, run only `npm run mhc:native:review:finalize -- --reading <safe-readingId>`; do not regenerate or conduct a second editorial review. For `recover_attach` or `recover_publish`, first run the checksum-bound `mhc:sync-latest` attachment for the selected local metadata, then metadata/content validation and the authorized manifest-last Drive publication. Run those publication steps only after the matching deterministic transaction contains `committed.json`, then verify exact readback and live health. Never let generation attach or publish. Safe-report only lane, reading ID/date, action/state/stage/code, and prior-manifest state—never private prose, source atoms, Scripture, comments, credentials, reader identities, URLs, hashes, Google IDs, or secrets; retain fallback and manifest on every failure.
